## 二、上线版本边界决策（v1.0 范围）

⚠️ 注意：本文档与《01》第八章"MVP 优先级"口径已统一并收紧。早期原型把活动日历/共修圈/疗愈师都画进了 MVP，但**上线是另一回事**——每多一个模块，就多一份资质、审核、运营、客服成本。务实建议首版聚焦"跑通核心闭环 + 现有素材能直接喂饱"。

### 2.1 v1.0 必含（上线最小集）

跑通一条主链路即可上线，证明产品成立：

| 模块 | 对应原型页 | 说明 |
|------|-----------|------|
| 启动问候页 | P01 | 节气仪式感，无强制登录 |
| 潮·发现页 | P02 + P12 | 今日推荐（规则推荐，非算法）+ 内容列表 + 内容详情 |
| 海·练习 | P03/P04/P05 | 呼吸练习工具 + 音频播放器（后台播放、定时） |
| 岛·我的 | P06/P08 | 基础个人中心 + 潮汐打卡（本地优先） |
| 内容管理后台 | — | 运营上传音频/图文，否则前端是空壳 |
| 危机援助入口 | 全局浮层 | **强制必做**，基于《危机干预与情绪急救箱.docx》 |

### 2.2 v1.0 建议含（素材已就绪，不加白不加）

现有素材能直接填充、几乎零额外成本的模块，建议首版一起上，否则首版太单薄：

| 模块 | 对应原型页 | 素材来源 |
|------|-----------|----------|
| 疗愈师列表/详情 | P15/P16 | `人物介绍.pptx` |
| 线下活动（瀑布流 + 详情） | P11/P19 | `活动:课程管理/` 方案库 + `空间照片/` |
| 报名成功闭环 | P14 | 微信支付（见第三节资质） |
| 课程列表/详情 | P17/P18 | `共时海冥想课程体系.docx` 等 |
| 共修圈 | P09 | 用现成架构，先支持"加入官方预置圈" |

### 2.3 推迟到 v1.x / v2.0（首版不做）

- 疗愈日记完整版（隐私合规成本高，首版先用"简易打卡"替代记录）
- 算法推荐（先用规则：时间/节气/天气）
- 会员体系 / 课程订阅 / 单次付费之外的复杂商业化
- 自由创建共修圈（首版只发布官方圈）
- 年度潮汐报告 / 月相回顾 / 情绪轨迹曲线

## 三、上线前置条件（最容易被忽略、最耽误时间）

**小程序不是有原型就能上线。以下任何一项卡住，都会让开发做完却发不出去。按优先级处理：**

### 3.1 微信账号与主体（第 1 周就要开始）

- [ ] **注册微信小程序账号**（微信号需企业/个体户主体，个人账号无法开通支付和内容类目）
- [ ] **微信认证**（300 元/年，必需，否则很多接口受限）
- [ ] **主体资质**：个体工商户或公司营业执照（成都共时海文化艺术发展有限公司已具备）
- [ ] 配置 **服务器域名白名单**（request / upload / downloadFile / socket）——后端没定之前无法调试线上环境

### 3.2 服务类目选择（合规核心，决定能不能过审）

疗愈/冥想/心理类在微信审核里是**高风险类目**，选错会被驳回甚至封禁。策略：

- ✅ **推荐类目**：`生活服务` / `教育（培训机构）` / `文化场馆` / `资讯` —— 以"身心放松内容 + 艺术 + 冥想课程"定位
- ❌ **规避类目**：`医疗健康` / `心理咨询`（需《医疗机构执业许可证》或心理咨询师资质，门槛极高且易触发"精神诊疗"红线）
- **关键声明**：产品内所有文案、协议、疗愈师介绍，必须标注"**非医疗诊断、非心理治疗，仅为身心放松与艺术表达**"。这与《00》"合规"原则一致，且是过审硬条件。

### 3.3 支付能力（涉及报名/课程付费时）

- [ ] 开通 **微信小程序支付**（需企业对公账户 + 商户号）
- [ ] 若不首版做付费，可先全部免费，跳过此步，但 P14 报名成功页的"支付"环节改为"免费报名/占位"，二期再接支付

### 3.4 隐私合规（微信强制）

- [ ] 编写 **《隐私保护指引》**（微信后台必填，列明收集哪些数据、用途）
- [ ] 在小程序内提供 **隐私协议弹窗**（首次启动同意）
- [ ] 《03》已规划的"数据导出/删除"接口（G3）虽标二期，但**隐私协议需声明支持**，建议首版预留后端接口

### 3.5 内容合规

- [ ] 音频/图文内容版权自检（现有素材为自有，无第三方侵权风险 ✅）
- [ ] **危机干预话术审核**：《危机干预与情绪急救箱.docx》内容需法务/心理专业复核，确保指引符合规范、不越界承诺"治疗"

## 四、技术架构方案

### 4.1 前端框架选型

| 方案 | 适合度 | 说明 |
|------|--------|------|
| **原生小程序** | ⭐⭐⭐⭐ | 最稳、审核最友好、性能好；原型已是 HTML，需转 WXML/WXSS。推荐 |
| Taro / uni-app | ⭐⭐⭐ | 若未来要多端（H5/抖音），可后期迁；首版不必增加复杂度 |
| **结论** | — | **首版用原生**，原型 HTML 作视觉参考，重写 WXML/WXSS，逻辑用 JS |

### 4.2 后端与存储

| 能力 | 推荐 | 说明 |
|------|------|------|
| 后端服务 | **微信云开发** 或 自建 Node 服务 | 云开发上手快、免运维，适合首版；体量上来再迁自建 |
| 数据库 | 云开发 DB / MySQL | 用户、打卡、报名、内容元数据 |
| 文件存储 | 云存储 / 对象存储 | 音频、海报、疗愈师照片 |
| 音频播放 | **BackgroundAudioManager** | 锁屏/退后台续播，是播放器核心（P05 已设计） |
| 推送 | 微信订阅消息 | 提醒（D1）、报名通知（P14）、共修圈（G1） |
| 支付 | 微信支付 API | 报名/课程付费 |
| 天气共时 | 天气 API（和风/高德） | A3，一期可做，成本低 |

### 4.3 工程结构建议

```
/miniprogram
  /pages
    /greet        P01
    /discover     P02 + P12 (列表+详情)
    /practice     P03 + P04 + P05
    /shore        P10 + P09 + P11 + P19
    /me           P06 + P08
    ...
  /components     呼吸圆环、潮汐打卡图、打卡卡等复用组件
  /utils          推荐规则、日期/节气、音频管理
  /api            后端接口封装
  app.js / app.json / app.wxss (全局，对应 common.css 变量)
```

### 4.4 设计资产复用到工程

- `common.css` 的 CSS 变量（潮汐蓝 #5B7B8A 等）转成 `app.wxss` 的全局样式
- 33 个原型页逐个转 WXML/WXSS，交互逻辑照《03》逐页实现
- 呼吸圆环动画、潮汐打卡图用 Canvas/SVG 在原生里重写（《03》已注明技术点）

## 七、合规与风险红线（必读）

1. **不做医疗承诺**：全站文案不得出现"治疗""治愈""诊断""疗程"等词；疗愈师介绍注明"非医疗执业"。
2. **危机干预谨慎**：弹窗提供倾诉渠道与求助指引，**不提供医疗建议**，话术需专业复核；高危词触发逻辑（《03》已规划）首版必须上线。
3. **隐私优先**：感受/日记默认私密、本地优先；分享为主动行为；隐私协议明示数据用途；预留导出/删除接口。
4. **未成年人**：不主动面向未成年人做付费引导；若涉及，需监护人同意流程。
5. **内容审核**：用户 UGC（共修圈打卡/感受）需内容安全接口过滤（微信 `msgSecCheck`），防违规。
6. **支付合规**：费率、退款规则在活动/课程详情明示；报名成功页注明"名额有限/不退改"等条款。

## 九、上线后：指标与迭代
