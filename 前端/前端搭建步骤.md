# 共时海小程序 · 前端搭建步骤与流程

> 配套：后端 `../后端/搭建步骤.md`（接口/登录/支付/部署）、设计文档 `../小程序设计方案/00~05`。
> 本文档告诉前端：**用什么技术、怎么从 33 个 HTML 原型转成真实小程序、按什么顺序做、联调与上线注意什么**。

---

## 〇、先定技术选型（重要）

| 方案 | 说明 | 我们的建议 |
|------|------|-----------|
| **原生小程序**（WXML/WXSS/JS） | 微信官方，零框架，原型是 HTML/CSS 直接可转 | ✅ **首选** |
| Taro / uni-app | 用 React/Vue 写，编译成小程序 | 若团队本就是 React/Vue 栈可选，但需额外翻译成本 |

**结论：用原生小程序。** 理由：
1. 原型是纯 HTML/CSS，原生 WXML/WXSS 是最近似映射，转换损失最小；
2. 团队无需引入额外框架与构建链，微信开发者工具开箱即用；
3. 后端返回结构 `{code,data,message}` 与小程序 `wx.request` 天然契合。

> 下文均按原生小程序写。若选 Taro，思路一致，只是 WXML→JSX、WXSS→CSS、页面路由→组件路由。

## 一、工程初始化

### 1.1 安装微信开发者工具
官网下载「稳定版」，安装后登录你们的小程序账号（或先用测试号）。

### 1.2 建项目
- 「导入项目」→ 目录选 `前端/miniprogram/`（本目录已备好 `project.config.json`）
- AppID：**开发期选「测试号」**；正式发布在微信公众平台注册后换成真实 AppID
- 后端编译类型：选「小程序」

### 1.3 后端先跑通（联调前置）
```bash
cd ../后端
npm install
cp .env.example .env        # 开发期可全留空，自动进入「开发模式」
npm run seed                # 建表 + 种子数据
npm start                  # http://localhost:3000
```
开发者工具里勾选 **「详情 → 本地设置 → 不校验合法域名、TLS」**，即可用 `http://localhost:3000/api` 联调。

## 三、设计 token：common.css → app.wxss

原型用 px、375 宽；小程序用 **rpx**，**750rpx = 屏幕宽 = 375px × 2**。
转换规则：**原型 1px = 2rpx**（字号、间距、圆角同乘 2；颜色照抄）。

`app.wxss` 顶部建议这样定义（已写入脚手架）：

```css
page{
  --tidal:#5B7B8A; --tidal-deep:#4A6B7A;        /* 潮汐蓝 主色 */
  --moonwhite:#F5F3EF; --mist:#ECE8E1;          /* 月白底 / 浅雾描边 */
  --wood:#C9B59A; --ink:#33393D; --smoke:#9AA0A4; /* 浅木 / 墨 / 灰 */
  --ink-green:#3F5E5A;                          /* 墨绿（月相/自然） */
  background:var(--moonwhite);
  font-family: "Songti SC","STSong",-apple-system,sans-serif;
  color:var(--ink);
}
```

> ⚠️ 小程序里 `page{--x:...}` 的 CSS 变量在部分基础库需写在 `app.wxss` 顶层或用 `:root` 等价写法（`page` 选择器即页面根）。组件内用 `var(--tidal)` 直接引用即可。

## 四、请求层：一次写好，全站复用

`utils/request.js`（脚手架已给）封装后端约定：

```js
const BASE = 'https://你的域名/api'   // 开发期填 http://localhost:3000/api
export function request(path, { method='GET', data, auth=true }={}) {
  return new Promise((resolve, reject) => {
    const header = { 'Content-Type': 'application/json' }
    if (auth) header.Authorization = 'Bearer ' + wx.getStorageSync('token')
    wx.request({
      url: BASE + path, method, data, header,
      success: res => {
        const b = res.data
        if (b.code === 0) resolve(b.data)
        else if (b.code === 401) { /* 跳登录 */ reject(b.message) }
        else reject(b.message)
      },
      fail: reject,
    })
  })
}
```

`utils/api.js` 把路径集中成常量（见脚手架），页面里只写 `api.dailyGreeting` 之类，避免硬编码。

## 五、页面开发工作流（每页都走这套）

把 `../页面原型/html/pXX-*.html` 转成小程序页，**四步**：

1. **拆外壳**：删掉 `.phone / .screen / .statusbar / .tabbar`（这些是预览外壳）。顶栏文字交给 `app.json` 的 `navigationBarTitleText` 或页面 `.json`；底部 4 Tab 交给 `app.json` 的 `tabBar`。
2. **结构 → WXML**：把 `.p-xxx` 容器内 HTML 改写为 WXML。注意：
   - `class` 保留；`id` 少用，用 `class` + `data-*`
   - 列表用 `<block wx:for="{{list}}">`
   - 点击事件 `bindtap="onTapX"`
   - 无 `href` 跳转：用 `wx.navigateTo({url})` / `wx.switchTab`（Tab 页）
3. **样式 → WXSS**：px × 2 成 rpx；`flex` 布局可直接复用；去掉 `position:fixed` 的手机框相关定位；动效用小程序支持的 `@keyframes`（呼吸圆环已验证可行）。
4. **行为 → JS + 接口**：`onLoad` 里 `request(api.xxx)` 拉数据；`data` 驱动渲染；按钮 `bindtap` 调接口或跳转；交互逻辑照 `../小程序设计方案/03-交互逻辑与按钮行为.md`。

**示例**：`pages/greet/` 已把 P01 完整转好，照这个范式写其余 32 页。

## 六、4 个 Tab 的处理

原型里 P02/P03/P10 等是带 `.tabbar` 的整页；真实小程序里：

- `app.json` 的 `tabBar` 配置 4 个 Tab：潮(discover) / 海(practice) / 岸(shore) / 岛(me)
- 每个 Tab 的「落地页」是独立 page（如 `pages/discover`、`pages/practice`、`pages/shore`、`pages/me`）
- 其它 29 页都是**非 Tab 页**，用 `wx.navigateTo` 从落地页点进去
- 切换 Tab 用 `wx.switchTab`，不能用 `navigateTo`

`app.json` 里 `tabBar` 的 `iconPath` 需要真实 png 图标（不能是文字/字体图标），见「设计交付规范」的图标清单。

## 七、动效与沉浸式页

- **呼吸圆环**（P04）：纯 CSS `@keyframes` 缩放，小程序支持，照搬 `p04-breathing.html` 的 `.breath-ring` 即可。
- **底部弹窗**（P21 日记 / P19 活动详情）：用 `components/bottom-sheet`（遮罩 + 上滑），比 `wx.showModal` 更贴合设计。
- **页面转场**：小程序默认左滑进栈。设计上要「慢」，可在 `app.json` 关掉不必要的动画或保持默认；**不要**自己做整屏翻转，违背平台习惯。
- **后台音频**：播放页（P05）用 `wx.getBackgroundAudioManager()`，切到别的页音乐继续播——这是 `../小程序设计方案/03` 已定规范。

## 九、上线前清单（与后端呼应）

1. **域名**：后端部署到 HTTPS 域名，在微信公众平台「服务器域名 → request 合法域名」加入。
2. **AppID**：`project.config.json` 与后端 `.env` 的 `WX_APPID/WX_SECRET` 用真实值。
3. **真实登录**：后端去掉开发模式（填真实 AppID/Secret），`wx.login` 走真实 `code2session`。
4. **微信支付**：活动报名若要真实收费，按 `../后端/搭建步骤.md` 第九节接 V3 支付（当前是模拟支付）。
5. **图标/素材**：把原型里的占位 unicode 字形（◷ ⊝ ▷ 等）全部换成真实图标 png/SVG；海报/疗愈师头像用公司真实素材。
6. **内容填充**：`../后端/src/db/seed.js` 的占位数据换成真实素材（冥想音频、疗愈师、活动）。
7. **合规**：全站文案不得出现「治疗/治愈/诊断」；危机援助弹窗保留且不可删（`/api/crisis`）。
8. **隐私**：`pages/settings` 提供数据导出/删除入口；日记/感受属敏感数据，存储按后端合规要求加密。

## 十一、常见坑

- **rpx 不是 px**：忘记 ×2 会导致元素偏小一半。原型量的是 375 宽，一律 ×2。
- **Tab 页不能用 navigateTo**：Tab 之间用 `switchTab`；非 Tab 页用 `navigateTo`/`redirectTo`。
- **tabBar 图标必须 png**：不支持字体图标/emoji，需设计导出 81×81px 图标。
- **storage 同步 API**：`wx.getStorageSync` 是同步的，登录态读取直接用，别包 Promise。
- **backgroundAudioManager 全局单例**：多页面共用同一个背景音频管理器，注意播放/暂停状态同步。
- **wx.request 并发限制**：一次最多 10 个，列表页注意节流。
